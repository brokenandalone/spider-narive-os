# Spider Audio Studio Wave 8: Count-In, Punch and Recording Integrity

## Integrated into the real native Studio bay

The existing **Record Audio · Multitrack** tab now exposes a recording
transport, not a second launcher. The owner can pick a private backing cue
generated by Auto Performer or Song Arranger, explicitly choose their input
and stereo output, and configure the following before recording:

- **Count-in:** zero to four bars at the explicit recording BPM (30–300)
  in 3/4 or 4/4. A bounded, synthesized metronome click plays into the
  *selected stereo cue output* before the actual backing begins. It is not
  routed to microphone monitoring and is not stored in the take WAV. The
  count-in click samples are generated before PortAudio opens, not in its
  real-time callback. Click accents distinguish the start of each bar.
- **Punch-in / punch-out:** an optional bounded recording window, expressed
  in backing-timeline seconds with 10 ms GUI precision and converted to exact
  integer sample frames. The input recording remains one full-length WAV
  aligned to backing time zero; samples outside the selected punch window
  are zeroed in the *finished* take. The input stream itself is active while
  the cue is playing. Old takes are never overwritten.
- **Manual latency:** prior +/- 250 ms input alignment is now applied
  before the punch mask. Positive values advance the recorded performance;
  negative values delay it. Mask boundaries are calculated on final,
  compensated sample indices.
- **Single duplex callback:** count-in and song audio run through the same
  explicit, selected full-duplex stream. Even when a PortAudio buffer straddles
  the very end of the count-in and first cue samples, the captured input is
  indexed from the first backing sample, NOT from the start of the click.
  No real-time disk access or audio-generation work occurs in that callback.
- **Safe stop and stalled hardware:** early stop produces silence for remaining
  unrecorded backing time. Frames are checked for continuity. Any audio
  overrun/underrun, input queue overflow, malformed buffers or a device that
  stops delivering callbacks triggers a reject/error and removes unpublished
  temporary files. Completed WAVs are published only to a new filename.
- **Read-only quality preview:** after capture, existing Studio QC scans the
  first and last two seconds of the *recorded take* and reports sampled peak
  dBFS and potential clipping or other warnings. A punch in the middle of a
  song may not be inside those windows, so a clean QC preview is NOT evidence
  that the entire take is clean. An inspection error cannot delete or alter
  the finished recording.

## Important limitations (still true)

The click and punch are source-stage developments covered by simulated
PortAudio tests, not a substitute for testing on the owner's actual
audio interface. Shared callback frame coordinates do not automatically
account for physical ADC vs DAC path delays, interface drivers, loopback
latency, CPU scheduling, speaker-to-mic bleed or different device clocks.
Use headphones. Manual latency compensation remains an estimate; calibrated
round-trip measurements, full input monitoring, MIDI/audio clock and low
latency PipeWire/JACK integration are still needed.

Count-in tempo is fixed to the owner's recording BPM, even if a MusicXML
score contains variable tempo changes. It does not yet implement a
tempo-map-aware cue click or song-wide transport automation. The virtual
band's SoundFont instruments are prerendered, not executing LLM inference
on the sound device's real-time thread. No commercial sample library, LV2
or VST host, punch lane comping, waveform crossfade or repair engine is
implied by this transport.

No system packages, sound-server routes or services were modified in this
GitHub feature branch. Recording still requires manual port selection and
owner action. The source is a DRAFT PR, not installed. Previous owner-modified
Spider OS native files must be reviewed and reconciled before safe delivery.

## Test coverage

- `tests/test_spider_overdub_transport.py`: deterministic click beats,
  sample boundaries, 3/4 accent and silence, invalid count-in values,
  invalid punch regions, compensated audio gating across chunk boundaries,
  full-duplex call-back buffers spanning click and cue, headphone cue never
  recorded into a vocal track, per-take output alignment, preflight before
  any hardware stream, and a simulated unresponsive device watchdog.
- `tests/test_spider_audio_gui.py`: count-in and punch controls appear in
  native Studio, default microphone stays closed, owner-selected backing
  updates recording rate and the suggested punch endpoint, and impossible
  punch points are rejected without opening the microphone.
- `tests/test_spider_audio_take_quality.py`: true 24-bit signed PCM sampled
  clipping/peak analysis and read-only source preservation.

Release manifest includes `studio/overdub_transport.py`. Existing Wave 5,
Wave 6 and Wave 7 code and tests remain intact.
